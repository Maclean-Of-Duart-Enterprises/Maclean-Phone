# Security Policy

## Reporting a Security Vulnerability

Maclean Of Duart Enterprises takes the security and privacy of its software and users seriously.

If you discover a security vulnerability in one of our projects, please report it responsibly and **do not publicly disclose the vulnerability until it has been reviewed and, where appropriate, corrected**.

## Preferred Reporting Method

Please email all the information on the vulnerability and send to office@macleanofduartenterprises.com.

When available, please use **GitHub Private Vulnerability Reporting** for the affected repository:

1. Open the affected GitHub repository.
2. Select **Security**.
3. Select **Advisories**.
4. Select **Report a vulnerability**.
5. Provide the information necessary to reproduce and evaluate the issue.

If private vulnerability reporting is unavailable for the repository, please contact Maclean Of Duart Enterprises privately rather than opening a public GitHub issue containing exploitable details.

## What to Include

Please provide as much of the following information as reasonably possible:

- A description of the vulnerability
- Affected application, repository, and version
- Affected Android, Linux, Windows, or other platform version
- Steps required to reproduce the issue
- Proof-of-concept information, when appropriate
- Potential security or privacy impact
- Relevant logs, screenshots, or error messages
- Any suggested mitigation or correction

Please remove passwords, API keys, authentication tokens, private keys, personal information, and other unrelated sensitive information before submitting logs or files.

## Responsible Disclosure

Security researchers are asked to:

- Report vulnerabilities privately before public disclosure.
- Allow reasonable time for investigation and remediation.
- Avoid accessing, modifying, destroying, or retaining data belonging to other people.
- Avoid privacy violations, service disruption, denial-of-service testing, social engineering, or destructive testing.
- Test only against systems, accounts, devices, and data you own or have explicit authorization to test.
- Make a good-faith effort to minimize potential harm.

## Security Issues vs. Ordinary Bugs

Please use the private security reporting process for vulnerabilities such as:

- Authentication or authorization bypasses
- Unauthorized data access or disclosure
- Arbitrary code execution
- Privilege escalation
- Injection vulnerabilities
- Cryptographic weaknesses that create a security impact
- Insecure handling of credentials or sensitive information
- Security-relevant Android component exposure
- Vulnerabilities allowing malicious applications or files to compromise the application
- Significant privacy vulnerabilities

Ordinary crashes, UI problems, feature requests, compatibility problems, and non-security bugs should generally be submitted through the repository's normal GitHub Issues system.

## Supported Versions

Security fixes are generally applied to the **latest maintained release** of each project.

Older versions may no longer receive security updates. Users are encouraged to use the latest available release whenever practical.

## Response Process

After receiving a vulnerability report, Maclean Of Duart Enterprises will attempt to:

1. Review and reproduce the reported vulnerability.
2. Determine its severity, scope, and affected versions.
3. Develop and test an appropriate correction or mitigation.
4. Release an updated version when necessary.
5. Coordinate disclosure of confirmed vulnerabilities when appropriate.

Complex vulnerabilities may require additional investigation and development time.

## Public Disclosure

Please do not publish exploit code or detailed vulnerability information before a correction or reasonable mitigation opportunity has been provided.

After remediation, vulnerability information may be published through a GitHub Security Advisory, release notes, or other appropriate documentation.

## No Bug Bounty Program

Unless explicitly stated otherwise for a particular repository, Maclean Of Duart Enterprises does **not currently operate a paid bug bounty program**.

Submission of a vulnerability report does not create an entitlement to payment, compensation, employment, or other consideration.

Responsible security research and reports are nevertheless appreciated.

## Scope

This policy applies to open-source software repositories maintained by:

**Maclean Of Duart Enterprises Corp**

Third-party libraries, operating systems, services, websites, and other dependencies may maintain their own security-reporting procedures. Vulnerabilities originating exclusively in a third-party component should generally also be reported to that component's maintainer.

## Security Updates

Users should monitor the applicable GitHub repository's **Releases** and **Security** sections for security-related updates.
